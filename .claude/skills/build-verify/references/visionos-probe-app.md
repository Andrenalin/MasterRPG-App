# Verifying visionOS/tvOS and RealityKit UI (probe app)

A green build is not enough for visionOS/tvOS SwiftUI changes: the first port of the map pin popover to visionOS compiled on all platforms but rendered broken (2026-10-02). Verify rendering before reporting done.

**Why:** Xcode MCP `RenderPreview` fails on visionOS with `NoStaticPreviews`, and `DeviceInteractionStartWorkspaceSession` only offers iOS simulators, so neither can drive or snapshot the visionOS app. The user had to report the visual bug themselves.

**How to apply:**
- If the user's simulator is booted, `xcrun simctl io <udid> screenshot` shows what they see (crop with `sips -c H W --cropOffset Y X`).
- To test a hypothesis, build a single-file SwiftUI probe in the scratchpad: `xcrun -sdk xrsimulator swiftc -parse-as-library -target arm64-apple-xros26.0-simulator main.swift -o Probe.app/Probe` (tvOS: `-sdk appletvsimulator`, `arm64-apple-tvos26.0-simulator`), hand-written Info.plist (`UIDeviceFamily` 7 = visionOS, 3 = tvOS), `codesign -s -`, `simctl install` / `launch`, screenshot. Pass variants with `SIMCTL_CHILD_<VAR>` env flags to bisect modifiers. Test one panel per run — two overlapping test panels interfered and gave a false result. Uninstall the probe (and shut down any simulator you booted) afterwards.
- Finding from that session: on visionOS, `glassBackgroundEffect` under a `.clipped()` ancestor draws its plate at the container origin and does not draw its content. The map canvas (`MapEditorCanvas`) is clipped, so overlays there use `.background(.regularMaterial, in:)` instead. `glassEffect` (Liquid Glass) on tvOS/iOS is fine under the same clip.
- Finding 2026-10-02 (3D table pin popover): in a RealityView *attachment* it is the other way round — `.regularMaterial` is all but invisible (no window behind it), while `glassBackgroundEffect(in:)` with a custom `InsettableShape` renders correctly. `@Environment(\.physicalMetrics).convert(points, to: .meters)` matches the attachment entity's bounds exactly.
- RealityKit content (iOS/macOS too): `RenderPreview` snapshots before RealityKit draws a frame, so a `RealityView` preview comes back empty. To see the real module view, temporarily expose it through a `public` wrapper, build the app for the simulator, then swiftc a scratch host with `-F <BUILT_PRODUCTS_DIR> -F <…>/PackageFrameworks -I <…>` and `-Xlinker -rpath -Xlinker @executable_path/Frameworks`, copy `MasterRPG.app/Frameworks` and its `*.bundle` into the probe, `codesign --deep`, install, screenshot. Remove the wrapper afterwards.
- macOS: `screencapture` has no screen-recording permission from this terminal; a CLI-launched probe can log to stdout instead, and in-process `NSApp.postEvent` mouse events (after `NSApp.activate`) do drive `.realityViewCameraControls(.orbit)`.
- Before booting or installing into a simulator, check `xcrun simctl list devices booted`: on 2026-10-02 the visionOS 27 simulator was already booted with the user's own MasterRPG session, and the probe was launched into it by mistake. If a simulator is already booted, leave it alone (never shut it down) and use the other Vision Pro simulator (visionOS 26.5, `13219D60-…`) for probes; shut down only what you booted.
