# Driving the iOS/iPadOS simulator through the Xcode MCP

Driving the app on an iOS/iPadOS simulator through the Xcode MCP (worked 2026-10-04):

- `DeviceInteractionStartWorkspaceSession` + `DeviceInteractionInstallAndRun` builds and installs, but that session key is then "not found" for `DeviceInteractionSynthesize`, and the app gets SIGTERMed when the run ends. Afterwards: `DeviceInteractionStartSession` (no workspace) + `xcrun simctl launch <udid> de.AndreTrettin.GameMaster`, then Synthesize works directly (no subagent needed).
- Bundle id is `de.AndreTrettin.GameMaster`; the process name is `MasterRPG`.
- Synthesize commands (verified 2026-10-08): `t x y` tap (points from the hierarchy file's `hitPoint`), `d x y` double tap, `drag x1 y1 x2 y2 0.3` is the **swipe/scroll** (a 0.5 duration did not scroll), `w seconds` wait; commands chain in one call (`t 451 54 w 2 t 364 432 w 3`). No command = capture only. `t x y 1.2` is a long press (context menu); `mt [x y] 1.0 [x y] 0.4 [x2 y2] 1.2 [x2 y2] 0.3` is a multi-touch keyframe sequence that works as drag-and-drop for `.draggable` rows (never start it inside the top bar, y < ~140: that drags the iPad window). Send one command per call and capture with a separate `w 2` call: chained taps often land before the UI is ready, and a downward list scroll is frequently ignored (relaunch the app if the list stops scrolling). The token for typing text is still unknown (`type`, `text`, `k`, `s`, `swipe`, `sw`, `scroll`, `m` are invalid). The full grammar table is embedded in `Xcode.app/Contents/PlugIns/IDEDeviceInteraction.framework` (command names blanked out).
- Entering text (verified 2026-10-09): the type command's token is still unknown (`kbd`, `i`, `tt`, `help` are invalid too) and `xcrun simctl pbcopy` left the iOS 27 simulator pasteboard empty. What works: tap the on-screen keyboard keys, whose `hitPoint`s are in the hierarchy (`Key` rows; `numbers`/`letters` switch layouts), chained as `t x y w 0.4 t x y …`.
- Software keyboard (verified 2026-10-09): the Xcode-hosted simulators count as having a hardware keyboard, so a focused field shows no on-screen keyboard and keyboard layout bugs do not reproduce. Force it with `xcrun simctl spawn <udid> defaults write com.apple.keyboard.preferences AutomaticMinimizationEnabled -bool NO` (domain `com.apple.Preferences` does nothing), then relaunch the app; write `YES` again afterwards (the original value). On iPad the keyboard's own hide key flips it back to `YES` and leaves a small floating bar.
- An interaction session is lost after about two minutes without a call (a slow Bash command in between is enough); start a new one, which relaunches the app, so unsaved edits of the open item are gone.
- A row under the list's navigation/search bar (y < ~140) cannot be tapped: the tap focuses the search field instead. Scroll it lower first.
- Folders are only list rows in the list's "Ordner" mode (list toolbar "Weitere" → "Ordner"); restore "Liste" afterwards. The iPad Air data has folders Bestie / Charakter / Spieler in Character but **no folder inside a folder**; build one temporarily with list menu "Ordner hinzufügen" + an `mt` drag of the new folder onto a row of an open folder's detail list, and remove it via the row's context menu afterwards.
- The hierarchy captured right after a tap can be mid-transition; capture again before trusting it.
- Navigator events (current / adding / pushing / presenting, with navigator name) go to the unified log: `xcrun simctl spawn <udid> log show --last 3m --style compact --info --predicate 'process == "MasterRPG" AND eventMessage CONTAINS "Navigator "'`. `log stream` with a BEGINSWITH predicate captured nothing.
- Simulator data: iPad Air 11-inch (M4) iOS 27 (`6ECE2C42-…`) has real data with folders (Character → folder "Bestie"). iPhone 18 Pro iOS 27 has only the bundled example data (no filled folders); filling a folder needs drag and drop.
- "iPhone 17 Pro" has no iOS 27 runtime, so `name=iPhone 17 Pro` destinations fail; use iPhone 18 Pro.
